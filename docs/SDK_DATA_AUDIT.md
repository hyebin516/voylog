# 외부 SDK 점검 — 무엇을 수집하고 어디로 보내는가

Play Console의 **데이터 보안(Data safety)** 양식은 앱이 실제로 하는 일과
한 줄씩 맞아야 한다. 잘못 신고하면 나중에 앱이 내려간다. 이 문서는 코드를
읽고 확인한 사실만 적는다. 설문 답변 자체는 [PLAY_LISTING.md](PLAY_LISTING.md).

기준: 2026년 11월 2일, `travel_youtube_app/pubspec.lock`

## 1. 개인정보에 닿는 SDK

| SDK | 버전 | 쓰는 곳 | 접근하는 정보 | 기기 밖으로 |
| --- | --- | --- | --- | --- |
| `geolocator` | 14.0.2 | 내 주변 추천, 뚜벅이 코스 시작점 | **정확한 위치** (`LocationAccuracy.high`) | 우리 서버로 좌표 전송. **저장하지 않고** 추천 계산에만 씀 |
| `firebase_messaging` | 16.7.0 | 푸시 알림 | **FCM 등록 토큰** (기기 식별자) | 우리 서버 `device_tokens`에 저장. 구글 FCM 서버 경유 |
| `kakao_flutter_sdk_user` | 2.0.0+1 | 카카오 로그인 | **카카오 회원번호, 닉네임, 이메일, 프로필 사진** (동의 항목에 한함) | 카카오 → 앱 → 우리 서버 `users` |
| `image_picker` | 1.2.3 | 프로필 사진 변경 | **사진 1장** (사용자가 직접 고른 것) | 512px로 줄여 우리 서버에 업로드 |
| `flutter_secure_storage` | 9.2.4 | 로그인 유지 | JWT, 사용자 ID | **나가지 않음.** OS 보안 저장소에만 |
| `share_plus` | 12.0.2 | 동선·장소 공유 | 사용자가 공유를 누른 내용 | 사용자가 고른 앱으로 (카톡 등) |

### 위치를 어떻게 다루는지

- **좌표 자체는 서버에 저장하지 않는다.** 추천을 계산할 때만 쓰고 버린다.
- 행동 기록(`recommendation_behaviors`)에는 좌표 대신 `0-200m` 같은 **반경
  구간**만 남긴다(`behavior.service.js`의 `bucketDistance`).
- 이동 경로, 방문 이력, 체류 시간은 **수집하지 않는다.**
- 권한은 사용자가 "내 주변 추천"을 열 때만 요청한다. 거부해도 앱의 나머지
  기능은 그대로 동작한다.
- 다만 추천·경로 계산을 위해 **좌표가 카카오 API로 전달**되므로, Play
  양식에서는 위치를 "공유함"으로 신고해야 한다.

## 2. 개인정보에 닿지 않는 SDK

| SDK | 버전 | 쓰는 곳 | 비고 |
| --- | --- | --- | --- |
| `dio` | 5.10.0 | 우리 서버 API 호출 | 네트워크 라이브러리. 자체 수집 없음 |
| `provider` | 6.1.5+1 | 상태 관리 | 앱 내부 전용 |
| `kakao_map_plugin` | 0.4.0 | 지도 렌더링 | 웹뷰로 카카오 지도 SDK 로드 |
| `webview_flutter_android` | 4.13.0 | 위 플러그인의 안드로이드 구현 | 디버그 빌드에서만 원격 디버깅 활성 |
| `youtube_player_iframe` | 6.0.2 | 영상 재생 | 유튜브 iframe. 유튜브 자체 쿠키가 생길 수 있음 |
| `url_launcher` | 6.3.2 | 카카오맵·약관 열기 | 외부 앱/브라우저 실행 |
| `path_provider` | 2.1.6 | 임시 파일 경로 | 공유 이미지 생성용 |
| `flutter_dotenv` | 6.0.1 | 설정값 읽기 | `.env`는 앱에 번들됨 |
| `firebase_core` | 4.15.0 | Firebase 초기화 | 메시징의 전제. 분석(Analytics) 미사용 |

**광고 SDK, 분석(Analytics) SDK, 크래시 리포팅 SDK는 사용하지 않는다.**
Firebase는 메시징만 쓰고 Analytics·Crashlytics는 포함하지 않았다.

## 3. 안드로이드 권한

| 권한 | 왜 필요한가 | 거부하면 |
| --- | --- | --- |
| `INTERNET` | 모든 기능 | 앱을 쓸 수 없음 |
| `ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION` | 내 주변 추천 | 그 기능만 못 씀 |
| `POST_NOTIFICATIONS` | 분석 완료·여행 시작 알림 | 알림만 안 옴 |

카메라·연락처·캘린더·저장소 전체 접근 권한은 **요청하지 않는다.** 사진은
시스템 선택기로 고른 한 장만 받으므로 저장소 권한이 필요 없다.

## 4. Play 데이터 보안 양식과의 대응

| 양식 항목 | 답 | 근거 |
| --- | --- | --- |
| 이름(닉네임) | 수집함 / 공유 안 함 / 필수 | `users.nickname` |
| 이메일 주소 | 수집함 / 공유 안 함 / 카카오는 동의 시 | `users.email` |
| 사진 | 수집함 / 공유 안 함 / 선택 | 프로필 사진 |
| 대략적·정확한 위치 | 수집함 / **공유함** / 선택 | 카카오 API로 전달 |
| 앱 활동 | 수집함 / 공유 안 함 / 선택 | 북마크·일정·조회 기록 |
| 기기 ID | 수집함 / 공유 안 함 / 선택 | FCM 토큰 |
| 전송 중 암호화 | 예 | 전 구간 HTTPS |
| 삭제 요청 수단 | 예 | 앱 내 회원 탈퇴 + 문의 창구 |

**"수집하지 않음"으로 신고하는 것들**: 연락처, 통화 기록, 문자, 캘린더,
건강·운동, 금융 정보, 사진 외 파일, 기기 내 다른 앱 목록, 광고 식별자.

## 5. 다시 확인해야 할 때

- 패키지를 추가하거나 버전을 올렸을 때
- 권한을 새로 요청하게 됐을 때
- Firebase에 Analytics나 Crashlytics를 켰을 때

위 세 가지 중 하나라도 해당하면 이 표와 Play 양식을 함께 고쳐야 한다.
앱에 포함된 의존성 전체 목록과 라이선스는 앱 내 **설정 > 오픈소스
라이선스**에서 볼 수 있다.
